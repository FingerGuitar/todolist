## 4. 阶段 1 — 桌面增强（基础加固）

> 修复已知问题，补全单机版短板，为后续企业级能力打基础

### 4.1 边栏任务同步（BUG-01）

**问题**：边栏窗口新建任务后，主窗口 Zustand store 不感知变化。

**方案**：

```text
边栏 BrowserWindow                    主 BrowserWindow
     │                                     │
     │── task:create (IPC) ──→ Main Process │
     │                           │          │
     │                           │ 写入 SQLite
     │                           │          │
     │                           │── webContents.send('data-changed', 'task')
     │                           │          │
     │                           ▼          ▼
     │                      两个窗口各自收到事件
     │                      各自调用 store.fetchTasks() 刷新
```

**实现要点**：
- 主进程：所有写操作（create/update/delete）完成后，向 **所有 BrowserWindow** 广播 `data-changed` 事件
- preload：监听 `data-changed`，暴露为 `window.api.onDataChanged(callback)`
- renderer：各 store 注册监听器，收到事件后自动 re-fetch

**关键代码变更**：

| 文件 | 变更 |
|:-----|:-----|
| `src/main/ipc-handlers.ts` | 写操作后调用 `broadcastDataChanged(channel)` |
| `src/preload/index.ts` | 新增 `onDataChanged` / `offDataChanged` 方法 |
| `src/preload/index.d.ts` | 补充类型声明 |
| `src/renderer/src/stores/task-store.ts` | `useEffect` 监听 `data-changed`，自动 re-fetch |
| `src/renderer/src/stores/category-store.ts` | 同上 |
| `src/renderer/src/stores/tag-store.ts` | 同上 |

### 4.2 应用自动更新（P-37）

**方案**：集成 `electron-updater`，支持私有服务器发布。

```text
构建流程:
  electron-builder → 生成 latest.yml + 安装包 → 上传到内网文件服务器

客户端:
  启动时静默检查 → 发现新版本 → 通知用户 → 后台下载 → 重启安装
```

**实现要点**：
- 安装依赖：`electron-updater`
- `src/main/updater.ts`：封装 `autoUpdater`，配置 `provider: 'generic'` + 内网 URL
- 渲染进程：设置页新增「检查更新」按钮，显示当前版本号
- `electron-builder.yml`：配置 `publish` 字段

### 4.3 数据库加密（P-32）

**方案**：替换 `better-sqlite3` 为 `better-sqlite3` + SQLCipher 构建，或使用 `@journeyapps/sqlcipher`。

**实现要点**：
- 首次启动生成随机密钥，存入系统 keychain（`keytar`）
- 数据库 PRAGMA：`PRAGMA key = 'xxx'`
- 迁移：检测旧版未加密 DB → 导出 → 新建加密 DB → 导入

## 5. 阶段 2 — 授权密钥系统

> 实现「一机一码」设备级授权管控

### 5.1 硬件指纹采集（P-01）

```text
采集维度:
  CPU ID      →  wmic cpu get ProcessorId (Windows)
  MAC 地址    →  网卡物理地址（排除虚拟网卡）
  磁盘序列号  →  wmic diskdrive get SerialNumber

指纹算法:
  fingerprint = SHA256(cpuId + macAddr + diskSerial + salt)
```

**文件规划**：
- `src/main/license/fingerprint.ts` — 采集+哈希
- 跨平台支持：Windows（wmic）、macOS（system_profiler）、Linux（dmidecode）

### 5.2 RSA 密钥签名（P-02）

```text
License 数据结构:
{
  "fingerprint": "sha256-hash",
  "tier": "enterprise",
  "maxDevices": 50,
  "expiresAt": "2027-12-31",
  "features": ["ai", "team", "admin"],
  "issuedAt": "2026-03-01"
}

签名: RSA-2048 私钥签名 → Base64 编码
验证: 客户端内置公钥 → 验签 + 检查有效期 + 对比指纹
```

**文件规划**：
- `src/main/license/validator.ts` — 客户端验证逻辑
- `src/main/license/types.ts` — License 数据类型定义

### 5.3 License Server（P-03）

```text
独立项目，非 Electron 客户端内部：

tech stack:
  Node.js + Fastify + PostgreSQL

API:
  POST /api/license/generate    — 管理员生成密钥
  POST /api/license/activate    — 客户端在线激活
  POST /api/license/verify      — 客户端定期校验
  POST /api/license/revoke      — 管理员吊销
  GET  /api/license/list        — 管理员查看所有授权
  GET  /api/license/audit-log   — 审计日志
```

**离线激活流程**：
1. 客户端导出指纹文件（JSON）
2. 管理员在 Server 端导入指纹 → 生成 License 文件
3. 客户端导入 License 文件 → 本地验签激活

## 6. 阶段 3 — AI 规划引擎增强

> 从基础子任务拆解升级为完整项目规划引擎

### 6.1 当前 AI 拆解能力（已实现）

```text
现状（F-11）:
  输入: 一个任务 taskId
  输出: subtasks[] = { title, description, priority }[]
  限制: 单轮、无依赖关系、无工时、无里程碑
```

### 6.2 增强目标

```text
升级后:
  输入: 一个任务（或自由文本描述）

  第 1 轮: AI 追问需求细节 → 用户补充
  第 2 轮: AI 输出拆解方案 → 用户确认/调整
  第 3 轮: AI 最终输出 →
    {
      subtasks: [
        {
          title, description, priority,
          estimatedHours: 4,
          dependencies: ["task-2"],
          milestone: "v1.0-数据层",
          risks: ["需要调研第三方API"]
        }
      ],
      milestones: [
        { name: "v1.0-数据层", deadline: "2026-03-15" }
      ],
      criticalPath: ["task-1", "task-3", "task-5"],
      totalEstimatedHours: 40
    }
```

### 6.3 实现方案

| 子功能 | 方案 | 改动 |
|:-------|:-----|:-----|
| 多轮对话 | 新增 `llm:plan-task` IPC，支持 `messages[]` 上下文传递 | `llm.ts` 新增 handler |
| 依赖关系 | LLM 输出 `dependencies` 字段，前端渲染 DAG 图 | 新增 `PlanningPanel` 组件 |
| 工时估算 | LLM Prompt 要求输出 `estimatedHours`，结合历史数据（平均完成时间） | Prompt 工程 |
| 里程碑 | LLM 自动按阶段分组，输出 milestone 列表 | 类型扩展 |
| 风险识别 | Prompt 要求标注技术风险点 | Prompt 工程 |
| 一键导入 | 将拆解结果批量调用 `task:create`，设置 parentId 形成任务树 | tasks 表需新增 `parent_id` 字段 |

### 6.4 tasks 表结构扩展

```sql

ALTER TABLE tasks ADD COLUMN estimated_hours REAL;
CREATE INDEX idx_tasks_parent_id ON tasks(parent_id);
```

## 7. 阶段 4 — 服务端基座

> 从单机桌面应用升级为 C/S 架构，这是团队版的根基

### 7.1 技术选型

| 层级 | 选型 | 理由 |
|:-----|:-----|:-----|
| Web 框架 | Fastify | 高性能，TypeScript 友好，插件生态成熟 |
| ORM | Drizzle ORM | 复用现有 schema 定义，迁移成本最低 |
| 数据库 | PostgreSQL 16 | 企业级、JSONB 支持、全文检索 |
| 缓存 | Redis 7 | 会话、Pub/Sub、在线状态 |
| 认证 | JWT (access + refresh token) | 无状态、可扩展 |
| 实时通信 | WebSocket (ws / Socket.IO) | 低延迟推送 |
| API 风格 | RESTful + JSON | 客户端兼容性好 |

### 7.3 数据库 schema 扩展

```sql
-- 用户表
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) NOT NULL UNIQUE,
  email VARCHAR(255) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  avatar VARCHAR(500),
  status SMALLINT NOT NULL DEFAULT 1,  -- 1=active, 0=disabled
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 团队表
CREATE TABLE teams (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  description TEXT DEFAULT '',
  owner_id INTEGER NOT NULL REFERENCES users(id),
  settings JSONB DEFAULT '{}',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 团队成员表
CREATE TABLE team_members (
  team_id INTEGER NOT NULL REFERENCES teams(id) ON DELETE CASCADE,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role VARCHAR(20) NOT NULL DEFAULT 'member',  -- admin/manager/leader/member
  joined_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  PRIMARY KEY (team_id, user_id)
);

-- 任务指派表
CREATE TABLE task_assignments (
  id SERIAL PRIMARY KEY,
  task_id INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  user_id INTEGER NOT NULL REFERENCES users(id),
  assigned_by INTEGER NOT NULL REFERENCES users(id),
  assigned_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 任务评论表
CREATE TABLE task_comments (
  id SERIAL PRIMARY KEY,
  task_id INTEGER NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  user_id INTEGER NOT NULL REFERENCES users(id),
  content TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 审计日志表
CREATE TABLE audit_logs (
  id BIGSERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  action VARCHAR(50) NOT NULL,       -- create/update/delete/assign/login
  entity_type VARCHAR(50) NOT NULL,  -- task/category/tag/user/team
  entity_id INTEGER,
  changes JSONB,                     -- { before: {...}, after: {...} }
  ip_address INET,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_audit_logs_user_id ON audit_logs(user_id);
CREATE INDEX idx_audit_logs_created_at ON audit_logs(created_at);
CREATE INDEX idx_audit_logs_entity ON audit_logs(entity_type, entity_id);

-- 现有表扩展
ALTER TABLE tasks ADD COLUMN team_id INTEGER REFERENCES teams(id);
ALTER TABLE tasks ADD COLUMN creator_id INTEGER REFERENCES users(id);
ALTER TABLE tasks ADD COLUMN assignee_id INTEGER REFERENCES users(id);
ALTER TABLE tasks ADD COLUMN parent_id INTEGER REFERENCES tasks(id) ON DELETE CASCADE;
ALTER TABLE tasks ADD COLUMN estimated_hours REAL;

ALTER TABLE categories ADD COLUMN team_id INTEGER REFERENCES teams(id);
ALTER TABLE tags ADD COLUMN team_id INTEGER REFERENCES teams(id);
```

### 7.4 客户端适配层

```text
当前数据流:
  Component → Zustand → window.api.task.list() → IPC → Main → SQLite

团队版数据流:
  Component → Zustand → window.api.task.list() → IPC → Main → HTTP → API Server → PostgreSQL

改造要点:
  1. 新增 src/main/api-client.ts — 封装 HTTP 请求（fetch + JWT）
  2. ipc-handlers.ts 按模式分发:
     - 单机模式 → 直接操作 SQLite（现有逻辑不变）
     - 团队模式 → 转发给 api-client → REST API
  3. 登录态管理: 主进程保存 JWT，自动刷新 refresh token
  4. 前端代码零改动，Zustand store 调用 window.api.* 接口不变
```

## 8. 阶段 5 — 团队协作

### 8.2 评论系统（P-20）

| 功能 | 描述 |
|:-----|:-----|
| 任务评论 | 任务详情页底部评论区，支持 Markdown |

| 附件引用 | 评论中可引用任务附件 |
| 编辑/删除 | 仅作者和管理员可操作 |

### 8.3 实时同步（P-31）

```text
WebSocket 事件流:

客户端 A 创建任务
     │
     ▼
  API Server
     │
     ├── 写入 PostgreSQL
     ├── 发布 Redis Pub/Sub: { event: 'task:created', teamId, data }
     │
     ▼
  WebSocket Gateway
     │
     ├── 推送给 客户端 B (同团队)
     ├── 推送给 客户端 C (同团队)
     └── 推送给 Web Dashboard (管理员)
```

**客户端处理**：
- 收到 `task:created` → task-store 追加新任务（乐观更新 or re-fetch）
- 收到 `task:updated` → 更新对应条目
- 收到 `task:deleted` → 移除对应条目
- 断线重连 → 全量 re-fetch 保证一致性

### 8.4 操作审计（P-21）

- API Server 中间件自动记录所有写操作到 `audit_logs` 表
- 记录内容：操作人、操作类型、实体类型、变更前后快照（JSONB diff）
- 管理驾驶舱提供全文检索和筛选

### 8.5 团队报告（P-22）

- 扩展现有 `llm:generate-report`，支持按团队维度聚合
- API Server 提供 `GET /api/report/team/{teamId}?type=daily|weekly`
- AI 汇总所有成员的工作成果，生成团队级报告
